# Границы исполнения и внешний контроллер (Execution Boundaries)

**Статус:** Архитектурный регламент исполнения

---

## 1. Разделение верификации и реального действия

```
[ Агент формирует заявку ] 
         │
         ▼
[ FinanceFxAdapter проверяет синтаксис и домены ]
         │
         ▼
[ SOL-Triad Core проверяет математику и инварианты (Вердикт: PASS) ]
         │
         ▼
[ Внешний Исполнительный Контроллер Хоста (Host Execution Controller) ]
         ├─► Если verdict == PASS -> Инициирует реальный платежный шлюз (SWIFT / Клиринг)
         └─► Иначе -> Блокирует транзакцию
```

### Чего система НЕ делает:
1. **Ядро и адаптер никогда не переводят деньги.** Вызов `FinanceFxAdapter.process_payment()` возвращает лишь математический вердикт (`PASS`, `REVIEW`, `FAIL`) и симулированные дельты.
2. Флаг `execution_permitted` в возвращаемом результате **всегда равен `False`**.
3. Ответственность за физическую или банковскую проводку денег целиком лежит на внешнем Исполнительном Контроллере хоста (`Host Execution Controller`), который обязан проверить полученный отчёт ядра и наличие прав перед отправкой запроса в реальный банковский API.
