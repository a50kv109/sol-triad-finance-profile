# SOL-Triad Finance Profile (`sol-triad-finance-profile`)

> **Официальная формулировка:**  
> «SOL-Triad Finance Profile — адаптируемая заготовка финансового модуля, предназначенная для настройки под процессы конкретной организации и требования применимой юрисдикции. Перед практическим использованием необходимо проверить и адаптировать её к действующим бухгалтерским, налоговым и иным релевантным нормативным требованиям, а также протестировать на целевых данных и процессах. Соответствие законодательству и корректность результатов не предполагаются автоматически и должны подтверждаться отдельно».

---

## 1. Назначение заготовки и архитектурные границы

SOL-Triad Finance Profile — это **базовая программная заготовка (адаптируемый каркас) финансового модуля**, предназначенная для последующей настройки, расширения и интеграции под конкретную компанию, организацию, финансовую систему или бухгалтерскую программу (например, 1С, ERP-системы, учетные контуры).

Модуль **не является** готовым универсальным бухгалтерским продуктом, самостоятельным платёжным ядром, банковским шлюзом, налоговым консультантом или утверждением о соответствии законодательству каких-либо стран.

### Типовая схема интеграции:
```
[ Бухгалтерская / Учётная система (1С, ERP и др.) ] 
       │
       ▼ (Экспорт данных / Запрос)
[ Адаптер конкретной системы (Custom Host Adapter) ]
       │
       ▼ (Финансовая задача / TaskRequest)
[ SOL-Triad Finance Module (Каркас / Skeleton) ]
       │
       ▼ (Трансляция в S, C, D)
[ SOL-Triad Core (Математическое ядро верификации) ]
       │
       ▼ (Вердикт: PASS / REVIEW / FAIL)
[ Внешний Исполнительный Контроллер (Host Execution Controller) ]
       │
       ▼ (Решение о проведении операции в учёте)
[ Возврат результата в бухгалтерскую систему ]
```

1. **Роль финансового модуля:** Задает исходную структуру и общие принципы обработки финансовых данных, разбора финансовой задачи и проверки её по правилам SOL-Triad Core. Архитектура может изменяться, расширяться и настраиваться под реальные бизнес-процессы конкретной организации.
2. **Разделение базового ядра и адаптаций:** Базовая заготовка отделена от страновых, отраслевых и корпоративных расширений. Все адаптации под конкретные компании, системы или юрисдикции оформляются как отдельные профили, конфигурации или дочерние расширения, чтобы изменения для одной среды не меняли базовую логику для остальных.
3. **Отсутствие готовых сертификатов:** Не заявляется о сертификации, официальном одобрении или готовой совместимости с конкретными системами (включая 1С и др.), пока не разработаны, не настроены и не проверены соответствующие проектные адаптеры.

---

## 2. Адаптация к стране и законодательству

1. **Нормативные требования:** Перед практическим использованием в конкретной юрисдикции модуль должен быть адаптирован к применимым местным требованиям: бухгалтерским стандартам, налоговым правилам, валютному регулированию, финансовому и иному относящемуся к задаче законодательству.
2. **Отраслевая специфика:** Учитываются также особенности конкретной отрасли, организационной структуры, учётной политики и целевой бухгалтерской программы.
3. **Экспертная проверка:** Исходная заготовка не может представляться как автоматически соответствующая законодательству какой-либо страны. Адаптацию, настройку правил и юридически значимые проверки должны проводить компетентные специалисты и эксперты соответствующей юрисдикции.

---

## 3. Границы ответственности

- Модуль сам по себе не заменяет бухгалтерскую, налоговую, финансовую или юридическую консультацию.
- Он не гарантирует законность или правильность результатов без корректных исходных данных, надлежащей настройки, тестирования и независимой проверки профильными специалистами.
- Функции, не реализованные в базовой заготовке (например, интеграция с конкретными API банков, поддержка специфических налоговых деклараций или многоуровневый клиринг), являются предполагаемыми направлениями развития и требуют самостоятельной реализации разработчиками хоста.

## 4. Статус реализации (Audit Status)

- **Реализовано (Implemented):** Базовые модели `TaskRequest`, `HostPolicy`, `FxPaymentResult` и каркас `FinanceFxAdapter` в `adapter.py`.
- **Проверено (Verified):** Набор модульных и интеграционных тестов ядра и адаптера в `sol-triad-core/tests` (100% прохождение тестов).
- **Симулируется (Simulated):** Проверка балансов, конверсия валют по курсам и проверка котировок в реестре в рамках демонстрационного стенда.
- **Не реализовано (Not Implemented):** Готовые страновые налоговые модули, сертифицированные интеграции с 1С/ERP, автоматическое соответствие местному законодательству.

## 5. Быстрый старт и запуск демонстрационного стенда

### Требования
- Python 3.9+
- Ядро `sol-triad-core`.

### Запуск тестов финансового адаптера
```bash
python3 sol-triad-core/tests/run_all_tests.py
```

### Запуск демонстрационного пайплайна
```bash
python3 sol-triad-core/examples/fx_payment_pipeline_demo.py
```
