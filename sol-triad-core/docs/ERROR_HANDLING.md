# Классификация диагностических кодов и обработка ошибок

**Статус:** Канонический справочник кодов (Diagnostic Codes & Fail-Closed Behavior)

---

## 1. Категории и степени важности (Severities)

Все сообщения верификации классифицируются по трём уровням:
- `ERROR`: Фатальное нарушение инварианта, полномочий или структуры. Всегда приводит к вердикту `FAIL`.
- `WARNING`: Эпистемическая неопределённость (устаревание данных, отсутствие подтверждения при отсутствии прямых нарушений). Приводит к вердикту `REVIEW`.
- `INFO`: Подтверждение успешного прохождения группы аксиом. Присутствует при `PASS`.

---

## 2. Полный реестр канонических диагностических кодов

### 2.1 Диагностики свидетельств и времени ($P_{SC}$)
| Код диагностики | Уровень | Описание ситуации |
|---|---|---|
| `EVIDENCE_PASS` | `INFO` | Свидетельство успешно подтверждено доверенным реестром и актуально. |
| `TEMPORAL_FUTURE` | `ERROR` | Временная метка свидетельства $t > t_{eval}$ (наблюдение из будущего). |
| `TEMPORAL_STALE` | `WARNING` | Возраст свидетельства превысил $\tau_{\max}$, требуется обновление. |
| `REGISTRY_OFFLINE` | `WARNING` | Реестр свидетельств недоступен, проверка не может быть завершена. |
| `EVIDENCE_NOT_FOUND` | `ERROR` | Запрошенный `evidence_id` отсутствует в авторитетном реестре. |
| `EVIDENCE_MISMATCH` | `ERROR` | Заявленный эпистемический статус не совпадает со статусом в реестре. |
| `EVIDENCE_DOMAIN_MISMATCH` | `ERROR` | Зарегистрированный домен свидетельства не входит в полномочия. |
| `EVIDENCE_HASH_MISSING_IN_REGISTRY` | `ERROR` | Запрос содержит хэш, но в реестре хэш отсутствует. |
| `EVIDENCE_HASH_REQUIRED_BY_REGISTRY`| `ERROR` | В реестре требуется хэш, но в запросе хэш не указан. |
| `EVIDENCE_PAYLOAD_MISMATCH` | `ERROR` | Хэш полезной нагрузки не совпадает с хэшем в реестре. |
| `INFERENCE_UNSUPPORTED` | `WARNING` | Вывод (`INFERENCE`) не содержит списка подкрепляющих доказательств. |
| `INFERENCE_CIRCULAR_DEPENDENCY` | `ERROR` | Посылка вывода ссылается на само свидетельство (цикл). |
| `INFERENCE_PREMISE_INVALID_STATUS`| `ERROR` | Посылка вывода имеет статус `UNKNOWN`. |

### 2.2 Диагностики полномочий и доменов ($P_{SC}, P_{SD}$)
| Код диагностики | Уровень | Описание ситуации |
|---|---|---|
| `SCOPE_PASS` | `INFO` | Домены, объекты и домены потерь полностью санкционированы. |
| `SCOPE_DEFECT_NONE` | `ERROR` | Одно из обязательных полей полномочий равно `None` (структурный дефект). |
| `SCOPE_EXCEEDED_DOMAIN` | `ERROR` | Домен ограничений $\mathcal{D}_C$ выходит за рамки полномочий источника $\mathcal{D}_S$. |
| `SCOPE_EXCEEDED_OBJECTS` | `ERROR` | Целевой объект $\mathcal{O}_C$ не входит в санкционированный список $\mathcal{O}_S$. |
| `SCOPE_EXCEEDED_LOSS` | `ERROR` | Запрашиваемый домен потерь $\mathcal{L}_D$ выходит за рамки $\mathcal{L}_S$. |

### 2.3 Диагностики физического состояния и инвариантов ($P_{CD}$)
| Код диагностики | Уровень | Описание ситуации |
|---|---|---|
| `STATE_PASS` | `INFO` | Симуляция терминального состояния успешна, все инварианты соблюдены. |
| `STATE_INVALID_NUMERIC` | `ERROR` | Обнаружено нечисловое значение ($NaN, \pm\infty$). |
| `STATE_NEGATIVE_RESOURCE_COST` | `ERROR` | Потребление ресурса отрицательно ($\Gamma < 0$). |
| `STATE_PROTECTED_PARAM_MUTATED`| `ERROR` | Попытка мутировать параметр из защищённого периметра (`protected_set`). |
| `STATE_PROTECTED_VALUE_MUTATED`| `ERROR` | Мутация изменила значение инвариантной константы. |
| `STATE_MIN_BOUND_BREACH` | `ERROR` | Терминальное значение параметра ниже минимальной границы ($V' < B_{\min}$). |
| `STATE_MAX_BOUND_BREACH` | `ERROR` | Терминальное значение параметра выше максимальной границы ($V' > B_{\max}$). |
| `STATE_MISSING_VAR` | `ERROR` | Ограничение задано для параметра, отсутствующего в состоянии системы. |
| `STATE_FLAG_MUTATED` | `ERROR` | Мутирован защищённый логический флаг из `protected_flags`. |
| `STATE_FORBIDDEN_FLAG_ACTIVE` | `ERROR` | Запрещённый флаг из `forbidden_flags` оказался в состоянии `True`. |
| `STATE_REQUIRED_FLAG_MISSING` | `ERROR` | Обязательный флаг из `required_flags` оказался в состоянии `False`. |
| `UNIT_INCOMPATIBLE` | `ERROR` | Несовместимые физические размерности или неизвестная единица измерения. |

### 2.4 Диагностики шлюза и адаптеров (Adapter Layer)
| Код диагностики | Уровень | Описание ситуации |
|---|---|---|
| `STRUCTURAL_DEFECT` | `ERROR` | Ошибка парсинга JSON, отсутствие обязательных полей или попытка инъекции. |
| `UNAUTHORIZED_LOSS_DOMAIN` | `ERROR` | Запрошенный агентом домен потерь отклонён политикой хоста до вызова ядра. |
| `ADAPTER_REJECTED` | `ERROR` | Общий статус отказа внешнего адаптера. |
